# Scheduled Automation Enhancements — Design Spec

**Date**: 2026-05-23
**Status**: Approved
**Author**: Alex Meyer
**Sub-project**: 4 of 5 (GitHub Integration)

## Summary

Three additions: (1) drift report pages become discoverable in the MkDocs nav via an auto-regenerated index, (2) a weekly cron workflow posts per-Epic progress summaries to GitHub Issues, (3) the architecture doc revision date is updated.

---

## 1. Drift Reports Nav

### Problem
`check_drift.py` writes `docs/drift-reports/YYYY-MM-DD.md` but those files are never added to `mkdocs.yml`, so they're orphaned — built into the site but invisible in the sidebar.

### Solution
- Add one static entry to `mkdocs.yml`: `Drift Reports: drift-reports/index.md`
- `check_drift.py` creates/regenerates `docs/drift-reports/index.md` on every run (whether or not drift was found), listing all `.md` files in that directory as a table
- The nightly workflow commits both the new report file and the updated index

No need to update `mkdocs.yml` per-report — the index page links to everything.

### `docs/drift-reports/index.md` format
```markdown
# Drift Reports

Nightly stale-requirement reports generated by check_drift.py.

| Date | Report |
|:---|:---|
| 2026-05-23 | [View](2026-05-23.md) |
```
Sorted newest-first. When no drift has ever been detected, shows "No drift reports yet."

## 2. Weekly Progress Summary

### New workflow: `.github/workflows/weekly-progress.yml`
- Trigger: `schedule: cron: "0 9 * * 1"` (every Monday 09:00 UTC) + `workflow_dispatch`
- Calls `python -m scripts.weekly_progress`

### `scripts/weekly_progress.py`

For each Epic Issue (one per stage):
1. Fetch the Epic's child UNs by looking up `requirement_map.yml` stage → UN list → Issue numbers from `github-issue-map.json`
2. Count verified vs total UNs
3. Post a comment on the Epic Issue with a progress table

Comment format:
```
## Weekly Progress — 2026-05-23

| User Need | Title | Status |
|:---|:---|:---|
| UN-010 | Spatio-temporal grouping | ✅ verified |
| UN-011 | Perceptual deduplication | 🔲 defined |

**2 / 5 verified (40%)**
```

Idempotent: the comment is always a new post (GitHub timestamps it), not an edit.
