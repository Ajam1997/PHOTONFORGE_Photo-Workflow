# #21 Stale sentinel file causes 5-minute hang after subprocess crash
# state: CLOSED
# labels: bug,plugin: lua,priority: medium
---
## Bug

``is_process_alive()`` in ``runner.lua:113-119`` only checks if the sentinel file (``%TEMP%/photonforge.running``) exists â€” it does not verify the process is actually running.

If the Python subprocess crashes (OOM kill, segfault, unhandled exception that bypasses ``atexit``), the sentinel file is left behind. The Lua polling loop sees the sentinel and assumes the process is still alive, so it keeps waiting.

The loop only exits when ``idle_count > MAX_IDLE`` (600 iterations at 500ms each = **~5 minutes**) or when the user clicks Stop.

```lua
local function is_process_alive()
  local fh = io.open(get_sentinel_path(), 'r')
  if fh then
    fh:close()
    return true  -- sentinel exists, but process may be dead!
  end
  return false
end
```

## Impact

After a crash, the UI appears stuck for up to 5 minutes with no indication that the subprocess has died.

## Suggested Fix

Cross-check the sentinel with actual process liveness:

```lua
local function is_process_alive()
  local fh = io.open(get_sentinel_path(), 'r')
  if not fh then return false end
  fh:close()

  local pid = read_pid_file()
  if not pid then return true end  -- can't check, assume alive

  if IS_WINDOWS then
    local code = os.execute('tasklist /FI "PID eq ' .. pid .. '" /NH | findstr ' .. pid .. ' >/dev/null 2>&1')
    return code == 0
  else
    local code = os.execute('kill -0 ' .. pid .. ' 2>/dev/null')
    return code == 0
  end
end
```

This verifies the PID is still a running process, and the polling loop would exit promptly after a crash.
