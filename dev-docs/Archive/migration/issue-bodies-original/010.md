## Bug

After stopping the pipeline mid-scan and resuming, the scan step restarts from file 0 instead of continuing where it left off.

## Root Cause

The scan command in src/photo_workflow/pipeline.py:270-301 iterates over ALL files in the source directory unconditionally. It uses INSERT OR IGNORE so the DB isn't corrupted, but every file is re-read for EXIF and re-emitted as progress â€” wasting time and resetting the UI counter to 0.

By contrast, dedup, score, and name all call get_pending(conn, table, stage) to skip files that already completed that stage. Scan is the only step missing this pattern.

Additionally, the Lua build_cmd() in lua/photonforge/runner.lua:52-59 explicitly excludes scan from both --resume and --force flags.

## Expected Behavior

On resume, scan should skip files already present in the DB with the scan stage completed, and start progress from the correct offset.

## Suggested Fix

**Python side** (pipeline.py):
- Use get_pending(conn, table, 'scan') or equivalent to get only un-scanned files
- Set progress total/done relative to remaining work

**Lua side** (runner.lua):
- No changes needed if Python handles it â€” scan is inherently idempotent via INSERT OR IGNORE
