## Problem

Live classification under the old single-axis genre router produced 81% "general" tags (3,770 / ~4,650 images). The new two-axis taxonomy (16 Subjects × 12 Photo Types) reduces the "unknown" sink by routing the failure modes into two independent axes — but it inherits the same underlying weakness: **CLIP prototypes are static and have no feedback loop from user corrections**.

Without calibration, the new axes will degrade the same way:
- Subject axis collapses toward dominant classes (`object`, `person`)
- Photo Type axis collapses toward the broad bucket (`documentary`, `candid`)
- Per-axis confidence stays below the 0.45 threshold → images fall through to "unclassified" on either or both axes

## Root Cause

`genre_router.py` runs dual-axis MobileCLIP classification against image-grounded prototypes (built once by `scripts/bruteforce_prototypes.py` from Unsplash Lite + COCO val2017 + Oxford-IIIT Pet, text-blended at α=0.7). EXIF priors apply independently per axis. **Nothing in the runtime path updates either prototype set based on observed errors in the user's library.** The brute-force calibration produces a fixed set, frozen at provision time.

## Proposed Solution

Support **per-axis calibration and back-training** of both prototype sets:

1. **Per-Axis Prototype Refinement** — Collect user corrections on Subject and Photo Type independently (a user may correct one axis while leaving the other intact). Re-estimate each axis's CLIP prototypes as centroids of corrected embeddings, preserving the exclusive-assignment + α=0.7 text-blend invariants from `bruteforce_prototypes.py`.
2. **Feature Augmentation** — Use `subject_area_ratio`, eye sharpness, face/animal/vehicle presence, EXIF focal length, and shutter speed to boost discrimination — especially on the Photo Type axis where CLIP alone underperforms (e.g. distinguishing `candid` from `street`, `portrait` from `still-life`).
3. **Learned Per-Axis Adapter** — Two independent logistic regression / LightGBM heads (one per axis) trained on user feedback; blend with image-grounded prototypes. Subject and Type adapters never share features after the CLIP backbone — they remain independent classifiers per the Stage 6 contract.
4. **Versioning** — Track Subject and Photo Type prototype versions separately. Allow per-axis rollback if calibration on one axis degrades without affecting the other.
5. **UI Integration** — Expose `subject_confidence` and `photo_type_confidence` as separate fields. Flag images where **either** axis falls below 0.45. Hierarchical Darktable tags (`photon|subject|*`, `photon|type|*`) already surface both axes — feedback collection reads corrections from either tag namespace.

## Stage 6 Alignment

Per `dev-docs/architecture/scoring-module-contracts.md`, Subject is the **region router** input and Photo Type is the **aesthetic weighter** input. Calibration quality on each axis has distinct downstream effects:
- **Subject errors** → wrong sub-score region routing (e.g. eye-sharpness check on a landscape)
- **Photo Type errors** → wrong aesthetic weight vector pulled from the `aesthetic_weights` SQLite table

Back-training therefore needs to report calibration F1 **per axis**, not as a single combined metric, because the two failure modes propagate differently through the scoring pipeline.

## Success Criteria

- Subject axis: < 10% of library on the broadest fallback class (`object`)
- Photo Type axis: < 10% on the broadest fallback class (`documentary`)
- Both `subject_confidence` and `photo_type_confidence` distributions shift right (median > 0.6)
- Per-axis F1 lift measurable on a hold-out test set after back-training on 500+ user-corrected images
- Manual override rate < 5% **per axis** independently
