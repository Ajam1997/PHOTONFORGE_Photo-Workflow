**Type:** Enhancement (Open)

## Feature

A new **experimental, opt-in** feature that uses online AI models to generate creative titles and Darktable edit presets for user-flagged photos. This is intentionally separate from the main offline pipeline and only runs on demand.

## Concept

After the standard pipeline (score -> name -> tag) has enriched a photo with genre, quality scores, descriptive names, and tags, a user can flag select photos for premium treatment. This feature would then:

1. **Creative titling**: Generate polished, creative titles using an online LLM, informed by all the metadata the pipeline has already produced (genre, scores, tags, Florence-2 caption, EXIF)
2. **Edit preset creation**: Analyze the photo's characteristics and generate a Darktable style/preset that selects appropriate modules and parameters for that photo's genre and qualities — automating the initial photo correction

## Architecture Notes

**This feature intentionally violates NFR-2.1 (100% offline at runtime).** It requires network access to call online models. This must be:
- Clearly documented as an experimental/optional feature
- Never triggered automatically by the pipeline
- Gated behind explicit user action (flag + activation)

## Prerequisites (must exist before this runs)

- Scoring complete (genre, sharpness, composition, exposure)
- Naming complete (Florence-2 caption, semantic description)
- Tagging complete (#15, #16)
- User flag set on the photo (Darktable color label or star threshold)

## Proposed Workflow

1. User runs the standard pipeline (ingest -> scan -> dedup -> score -> name)
2. User reviews results in Darktable and flags photos for creative processing
3. User triggers the creative step from the plugin panel (separate button, not part of the standard Run)
4. The feature queries only flagged photos, collects their metadata, and calls the online model
5. Results are written back: creative title to description, edit preset to Darktable style

## Edit Preset Generation (detail)

The goal is to map the photo's profile to appropriate Darktable module settings:

| Photo Profile | Suggested Modules |
|---|---|
| Landscape, well-exposed | filmic, color balance, local contrast |
| Portrait, soft lighting | filmic, skin tone, portrait mask |
| Wildlife, high-sharpness | sharpening, denoise, crop |
| Low-light street | denoise (profiled), exposure lift, filmic |

The online model would receive the photo's metadata and generate a Darktable style (.dtstyle XML) or lua-based preset that the applicator writes to the image.

## Open Questions

- Which online model/API? (Claude, GPT-4V, Gemini — needs multimodal for edit preset quality)
- Should the photo itself be sent to the online model, or only the metadata?
- Darktable style format: .dtstyle XML file vs. Lua-driven module parameter setting?
- Cost/rate-limiting for batch processing of flagged photos
- Privacy implications of sending photos to online APIs

## Dependencies

- #15 (genre to tags)
- #16 (naming overhaul — richer metadata for the online model to work with)

## Scope

This is a design/exploration issue. Implementation should start with a proof of concept on a single genre (e.g. landscape) before expanding.
