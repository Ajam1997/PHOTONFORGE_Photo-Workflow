## Problem

The current Darktable Lua plugin UI has poor observability during and after pipeline runs:

1. **Log is a wall of text**: The text_view log shows raw lines like [14:32:05] scan DSC00142.ARW [ok] with no visual hierarchy, no severity distinction, and no way to tell what matters at a glance.

2. **No in-panel progress indicator**: The only progress feedback is Darktable's bottom job bar (dt.gui.create_job). In the plugin panel itself, there's no counter or progress text showing e.g. Scoring: 42/100. You have to watch lines scroll by and guess.

3. **Step status is unclear**: Each step just shows last: 2026-05-22 14:30 checkmark next to its checkbox. There's no indication of *currently running*, *pending*, *skipped*, or *failed with error*. After a run, it's hard to tell at a glance what succeeded vs. failed.

4. **No post-run summary**: When a multi-step run finishes, the log just says Pipeline complete. with no summary of what was done (files processed, errors, time elapsed).

## Current Implementation

- **Log**: panel.lua:182-193 — plain text_view, lines appended with table.concat
- **Progress**: runner.lua:228-233 — only updates job.percent on Darktable's job bar
- **Status labels**: panel.lua:169-171 — static last: timestamp labels
- **Log format**: runner.lua:235-236 — [HH:MM:SS] step file [status]

## Proposed Improvements

### 1. In-panel progress label per step
Add a dynamic label above or below the log that shows the active step and count:

Scoring: 42/100  |  Step 3/5

This would be updated from runner.lua whenever a _progress JSON record is received. Darktable's Lua API supports updating label.label dynamically.

### 2. Step status indicators
Replace the static last: labels with state-aware text:

| State | Display |
|-------|---------|
| Pending | -- (grey) |
| Running | Running... |
| Done | Done 14:30 (142 files) |
| Failed | FAILED 14:30 |
| Skipped | Skipped |

Update update_status() in panel.lua to accept richer state info, and have runner.lua call it at step start/end/fail.

### 3. Structured log lines
Format log entries with clearer structure:

- Step headers: --- Step 2/5: score --- (already present, good)
- File progress: [14:32:05] score  42/100  DSC00142.ARW  ok
- Errors: [14:32:05] score  42/100  DSC00142.ARW  FAILED: <reason>
- Summary: include done/total counter inline with each file

### 4. Post-run summary
After run_all completes, emit a summary block:



This requires runner.lua to track elapsed time per step (os.clock() or os.time() deltas) and file counts.

## Darktable Lua Constraints

- No native progress bar widget — must simulate with label text
- UI updates only happen when yielding via dt.control.sleep() (single-threaded Lua)
- dt.print() can be used for toast notifications on completion
- Widget tree is built once at load time; dynamic changes are limited to updating label.label, text_view.text, etc.
