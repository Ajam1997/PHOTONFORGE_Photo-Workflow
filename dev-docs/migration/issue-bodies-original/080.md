## Summary

Improve Florence-2 caption quality by feeding the new scoring system's outputs (Subject tag, Photo Type tag, YOLO detections, exposure style) as grounding prompts. Strict quality win at near-zero compute cost.

## Context

This was identified during the scoring system redesign (see `docs/architecture/scoring-module-contracts.md`). Once the two-axis tag system lands, every image will already have:

- Subject tag (one of 16)
- Photo Type tag (one of 12)
- YOLO detections with bboxes
- Exposure style (normal / high_key / low_key / silhouette)
- Face count and landmarks

Florence-2 currently ignores all of this and re-derives scene content from scratch â€” leading to hallucinated content, generic captions, and missed grounding opportunities.

## Goal

Pass the above outputs into Florence-2's prompted-captioning interface so:

1. Captions are grounded in the same scene understanding the rest of the pipeline uses (no contradictions between the Subject tag and the caption).
2. Florence-2 stops hallucinating objects YOLO didn't detect.
3. Captions become richer when scene context is unambiguous (Florence-2 can spend its capacity on verbs, relationships, and mood rather than re-identifying the dog).

## Scope

**In scope:**
- Modify `naming.py` (or the caption-producing module) to construct grounded Florence-2 prompts from the upstream tag/detection outputs.
- Validate Florence-2 actually respects the grounding for the prompt variants we choose (some prompts get ignored by Florence-2).
- A/B comparison: ungrounded vs. grounded captions on a 50-image test set; report on caption quality, hallucination rate, and elapsed time.

**Out of scope:**
- The lazy/cull-gated execution model for Florence-2 (Option C from the design discussion). Tracked separately â€” depends on the cull pipeline.
- Replacing Florence-2 with templates (rejected â€” Option A).
- Filename template redesign (separate concern; Florence-2 stops being the filename source in Option C work).

## Dependencies

**Blocked by:** scoring-system refactor merge â€” needs the new two-axis tag outputs to be available in the pipeline before grounding prompts can be built. See `docs/architecture/scoring-module-contracts.md` for the contracts.

## Success criteria

- [ ] Florence-2 prompt construction wired to consume `GenreResult` + `SubScoreBundle` (or equivalent post-refactor types).
- [ ] A/B comparison on 50 fixture images shows grounded captions are at least as accurate as ungrounded, with measurable reduction in hallucinated content.
- [ ] No regression in KPM-1.2 (Florence-2 inference <= 2.5s/image).
- [ ] Unit tests cover the prompt-construction logic (input: tag/detection set, output: prompt string).
