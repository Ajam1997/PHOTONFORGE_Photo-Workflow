## Problem

Ingest of ~100 ARW files (~4GB from SD) feels slow. KPM-1.1 targets >= 80% USB 3.0 bandwidth but several bottlenecks in src/photo_workflow/ingest.py prevent that.

## Bottlenecks Identified

### 1. Per-file DB commit (biggest impact)
insert_photo() in photondb.py:95 calls conn.commit() after every single file. Each commit forces an fsync to disk. For 100 files that is 100 fsyncs â€” significant overhead. Batching commits (e.g. every 10-20 files, or wrapping the whole loop in a transaction) would dramatically reduce this.

### 2. Silent EXIF reading phase (perceived slowness)
Before any copying starts, _read_exif_timestamp() is called for every source file (line 94-95) to sort by timestamp and check for already-ingested files. For 100 ARW files on an SD card, this involves 100 random reads with no progress output to the UI. The user sees nothing happening during this phase.

### 3. Single-threaded sequential copy
shutil.copy2 copies files one at a time (line 119). For large ARW files (~40MB each), there may be an opportunity to overlap EXIF reading of the next file with the copy of the current file, though the single SD card bus is likely the real bottleneck here.

### 4. Double volume label read
get_volume_label(dest) is called both in pipeline.py:244 and again in ingest.py:78. Minor, but unnecessary I/O.

## Suggested Fixes (in priority order)

1. **Batch DB commits**: Use conn.execute() without per-file commit, then conn.commit() every N files or at the end. Wrap in a transaction for atomicity.
2. **Emit progress during EXIF phase**: Add a progress emission pass so the UI shows Reading EXIF 1/100... before copying starts.
3. **Consider shutil.copy2 buffer size**: The default buffer may not be optimal for large files over USB. shutil.copyfileobj with a larger buffer (e.g. 1MB) could help.
4. **Remove duplicate volume label call**.

## Environment

- ~100 Sony ARW files (~40MB each)
- SD card reader on Yoga 910 (USB 3.0)
- Destination: external SSD (PHOTON cartridge)
