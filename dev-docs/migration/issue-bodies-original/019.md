# #19 Windows: Stop button silently fails if PID file not yet written
# state: CLOSED
# labels: bug,priority: high,plugin: lua
---
## Bug

On Windows, ``M.kill()`` in ``runner.lua:122-136`` can only kill the subprocess via ``taskkill /F /PID``. If the PID file hasn't been written yet (race condition during process startup), ``read_pid_file()`` returns nil and **nothing happens** â€” the process keeps running.

On Linux, there's a ``pkill -f 'photo-workflow'`` fallback (line 133). On Windows, there is no equivalent fallback.

```lua
if IS_WINDOWS then
    if pid then
      os.execute('taskkill /F /PID ' .. pid .. ' >/dev/null 2>&1')
    end
    -- no else! if pid is nil, nothing happens
else
    if pid then
      os.execute('kill -9 ' .. pid .. ' 2>/dev/null')
    else
      os.execute('pkill -f \'photo-workflow\' 2>/dev/null')  -- fallback!
    end
end
```

## Impact

Combined with #9 (delayed stop), this means on Windows the Stop button can completely fail to kill the subprocess, especially during fast steps like scan where the Python process may start and finish before the PID file is read.

## Suggested Fix

Add a Windows fallback using ``taskkill`` by image name:

```lua
if IS_WINDOWS then
    if pid then
        os.execute('taskkill /F /PID ' .. pid .. ' >/dev/null 2>&1')
    else
        os.execute('taskkill /F /IM python.exe /FI "WINDOWTITLE eq photo-workflow" >/dev/null 2>&1')
        -- or: use wmic/Get-Process to find by command line
    end
end
```

Alternatively, use ``taskkill /F /T /PID`` to also kill the cmd.exe parent and its process tree.
