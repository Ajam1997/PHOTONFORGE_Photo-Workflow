**Type:** Enhancement (Open)

## Context

FR-1.7.2 introduces multi-genre tagging with a single blended `master_score` computed from a confidence-weighted sum of per-genre GENRE_WEIGHTS.

A wildlife-portrait might legitimately score 4 stars when judged as a portrait but 2 stars when judged as a wildlife shot. The current single-blended scalar collapses that information.

## Proposal

In addition to `master_score`, store and surface per-genre scores:

```python
@dataclass
class FusionResult:
    master_score: float                          # existing — blended
    per_genre_scores: dict[str, float]           # new — score under each detected genre's weight template
    ...
```

XMP:
```xml
<photon:PerGenreScores>
  <rdf:Bag>
    <rdf:li>wildlife=0.62</rdf:li>
    <rdf:li>portrait=0.84</rdf:li>
  </rdf:Bag>
</photon:PerGenreScores>
```

photonforge.db: new column `per_genre_scores TEXT DEFAULT ''` (JSON).

## Why later, not now

Decided in design discussion (2026-05-25): start with single blended `master_score` to ship FR-1.7.2 sooner. Per-genre breakdown is additive — can be added without breaking the blended scalar. Defer until we see whether users actually need the disaggregated view in Darktable.

## Acceptance

- `per_genre_scores` populated for every multi-genre image
- Visible in Darktable Lua plugin as expandable detail next to star rating
- Existing `master_score` field continues to work for legacy queries
