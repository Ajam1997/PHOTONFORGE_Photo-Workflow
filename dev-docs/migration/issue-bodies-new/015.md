**Type:** Enhancement (Closed)

## Feature

The scoring step already computes a genre classification (e.g. wildlife, landscape, portrait, street, macro) and stores it in the DB (``genre`` column in photondb), but this data is never written to the Darktable image metadata. It should be applied as a Darktable tag/category so users can filter and organize their library by genre.

## Current State

- **Scoring emits genre**: ``pipeline.py:470`` emits ``genre=fusion.genre`` in the JSON progress output
- **DB stores genre**: ``photondb.py:54`` has ``genre TEXT`` and ``genre_confidence REAL`` columns
- **Applicator ignores genre**: ``applicator.lua:41-52`` handles the score step but only writes ``rating``, ``color labels``, score notes, and original filename — genre is dropped on the floor

## Proposed Change

### Python side
Genre is already emitted in the JSON. No changes needed.

### Lua side (``applicator.lua``)
In the ``rec.step == 'score'`` branch, write the genre to Darktable tags:

```lua
if rec.genre ~= nil and rec.genre ~= '' then
  local tag = dt.tags.create('PHOTONForge|' .. rec.genre)
  dt.tags.attach(tag, img)
end
```

This creates a hierarchical tag (e.g. ``PHOTONForge|wildlife``, ``PHOTONForge|landscape``) that appears in Darktable's tag list and can be used for filtering, smart collections, and export.

## Notes

- Use a ``PHOTONForge|`` prefix to namespace the tags and avoid collisions with user tags
- Consider a confidence threshold — only tag if ``genre_confidence`` is above a minimum (e.g. 0.5) to avoid noisy classifications
