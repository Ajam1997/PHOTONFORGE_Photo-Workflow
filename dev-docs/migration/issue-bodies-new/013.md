**Type:** Engineering task (Closed)

## Problem

The dedup step is slow for ~100 ARW files. Multiple bottlenecks compound.

## Bottlenecks Identified

### 1. cluster_sessions re-reads EXIF from disk (biggest impact)
``cluster_sessions()`` in ``grouping.py:36`` calls ``read_exif_datetime(rec.path)`` for every file, which opens each ~40MB ARW via ``exifread``. But these timestamps were already read during ingest/scan and are stored in the DB as ``exif_timestamp``. The dedup command loads all rows at ``pipeline.py:334`` and has access to the stored timestamps — it should use them instead of re-reading from disk.

### 2. No dHash caching
``_dhash()`` in ``dedup.py:13`` computes a perceptual hash by opening each RAW file via ``rawpy.imread()`` + ``extract_thumb()`` + ``imagehash.dhash()`` on every run. These hashes are deterministic — once computed, they could be stored in the DB (e.g. a ``dhash`` integer column) and reused on subsequent runs. This would make re-runs and resume near-instant.

### 3. Per-file DB commits in update_stages
``update_stages()`` in ``photondb.py:112`` calls ``conn.commit()`` after every file. For 100 files, that is 100 fsyncs. The dedup command already does its own batch commit at ``pipeline.py:361`` for the session/duplicate updates, but the ``update_stages`` calls (line 357) each commit individually.

### 4. Processes ALL rows, not just pending
``pipeline.py:334`` loads all rows and runs ``cluster_sessions`` on all of them, even when only a few files are pending dedup. Session clustering should be able to reuse stored ``session_id`` values for already-processed files.

### 5. update_stages does SELECT before UPDATE per file
``photondb.py:101-111`` does a SELECT to read the current stages, then an UPDATE — 2 queries + commit per file (3 round trips). Could be a single UPDATE with string concatenation in SQL, or batched.

## Suggested Fixes (priority order)

1. **Use DB timestamps for clustering**: Pass ``exif_timestamp`` from the DB row into ``cluster_sessions`` instead of calling ``read_exif_datetime()`` on each file. Eliminates 100 raw file opens.
2. **Cache dHash in DB**: Add a ``dhash INTEGER`` column. Compute only for files with ``dhash IS NULL``. Eliminates rawpy opens on re-runs.
3. **Batch commits**: Remove the per-call ``conn.commit()`` from ``update_stages`` and let the caller control transaction boundaries.
4. **Skip already-clustered files**: Only re-cluster pending files; reuse stored ``session_id`` for completed ones.
