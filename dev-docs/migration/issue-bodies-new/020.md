**Type:** Bug (Closed)

## Bug

The scan step in ``pipeline.py:289-294`` emits per-file ``scan ok`` events but never emits a ``_progress`` event during processing. The only ``_progress`` is emitted at the very end (line 301) with ``done == total``, jumping from 0% to 100% instantly.

```python
# During the loop — no _progress emitted:
for p in photos:
    ...
    emit('scan', p.name, 'ok', json_progress=json_progress)

# Only at the end:
click.echo(json.dumps({'step': '_progress', 'done': len(photos), 'total': len(photos)}))
```

Every other step (dedup, score, name) emits ``_progress`` during processing so the Lua poller can update ``job.percent``. Scan is the only step missing this.

## Impact

The Darktable job progress bar stays at 0% for the entire scan step, then jumps to 100%. For large folders this makes it look like the plugin is stuck.

## Fix

Add a ``_progress`` emission inside the scan loop:

```python
for i, p in enumerate(photos, 1):
    ...
    emit('scan', p.name, 'ok', json_progress=json_progress)
    if json_progress and i % 10 == 0:
        click.echo(json.dumps({'step': '_progress', 'done': i, 'total': len(photos)}))
```
