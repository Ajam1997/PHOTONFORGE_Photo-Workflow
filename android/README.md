# PhotonForge Android — Phase 2 headless core

Kotlin port of the PHOTONForge scoring pipeline for on-device culling
(Pixel 9 Pro XL target). Design: `dev-docs/architecture/android-port-brief.md`.

## Modules

- **`core/`** — pure-JVM Kotlin: scoring math (sharpness/composition/exposure),
  two-axis genre routing, score fusion + star rating, dHash dedup, session
  grouping, ARW embedded-preview extraction (TIFF/IFD parser), XMP sidecar
  parse-modify-write. **Verified against the Python reference** by golden-vector
  tests (`core/src/test`): fixtures are generated by `tools/generate_golden.py`
  running the actual desktop code.
- **`app/`** — the Android shell: ONNX Runtime (CPU/XNNPACK) engines behind the
  `InferenceEngine`/`EngineRegistry` seam (NPU-ready per brief §7.4), SAF I/O,
  and the Phase 2 debug/benchmark screen. Needs the Android SDK; `settings.gradle.kts`
  auto-skips it on plain-JVM machines so `:core:test` runs anywhere.

## Bundled assets (single source of truth)

`core/src/main/resources/photonforge/{weights,adapter,prototypes}.json` are
exported from `src/photo_workflow/data/genre_weights.db` + `score_fusion.py` by
`tools/export_assets.py`. Re-run + commit after any recalibration that should
ship to the app.

## Build & install (your machine)

1. Android Studio (Ladybug+) → *Open* → this `android/` directory. The SDK
   (API 35) installs via the SDK Manager on first sync.
2. `Build > Build APK(s)` or from a terminal with the SDK installed:

   ```bash
   cd android
   ./gradlew :app:assembleDebug
   adb install app/build/outputs/apk/debug/app-debug.apk
   ```

   (Enable Developer options + USB debugging on the phone first.)

## Provision the models onto the phone

The APK bundles no ONNX models. Put the **scoring** model tree (~85 MB) on the
device or cartridge — the same directory layout the desktop uses:

```
models/
├── mobileclip_s2_int8/vision_encoder.onnx   (required)
├── rmbg14_int8/model.onnx                   (optional — full-frame mask without it)
├── yunet/face_detection_yunet.onnx          (optional — no face signals without it)
├── yolov8n_int8/model.onnx                  (optional — no object signals without it)
└── clip_aesthetic_head/aesthetic_mlp.onnx   (optional — aesthetic dropped without it)
```

Copy from a provisioned desktop (`scripts/provision_scoring_models.py` output),
either onto the exFAT cartridge (`<DRIVE>/models/` — the PR #140 layout) or to
phone storage (`adb push models /sdcard/Download/photonforge-models`).

## Run the Phase 2 harness

1. Open **PhotonForge** → *Pick models dir* → select the `models/` folder
   (on the USB drive or local storage).
2. *Pick photos dir* → the folder with `.ARW` files (USB-C drive / SD reader
   mounts appear in the SAF picker's drawer).
3. *Run pipeline*. Per-frame timings stream on screen; the full benchmark CSV
   lands in `Android/data/com.photonforge.app/files/benchmarks/run-<ts>.csv`
   (per-stage ms, preview dimensions, thermal headroom/status, scores).
4. XMP sidecars (`IMG.ARW.xmp`) are written next to the files —
   parse-modify-write; open the folder in desktop darktable to see
   ratings/labels/`photon|*` tags.

To pull the CSV: `adb pull /sdcard/Android/data/com.photonforge.app/files/benchmarks .`

## Verify the core on any machine (no Android SDK)

```bash
cd android && gradle :core:test
```

Golden-vector regeneration (after changing the Python reference):

```bash
python3 android/tools/export_assets.py
python3 android/tools/generate_golden.py
```

## Phase 2 scope notes

- Genre routing uses the **learned adapter** (bundled, active in the training
  DB); the no-adapter fallback is CLIP-prototype-only — the full five-expert
  product-of-experts is a Phase 3+ item (brief §"model inventory").
- Florence-2 naming is **off** (toggle stubbed in the UI, Phase 6).
- dHash uses bilinear resample (PIL uses Lanczos): hashes are self-consistent
  on device but not bit-identical to desktop-computed ones.
- The final per-shoot `hybrid_star` re-rating is computed and reported in the
  log; sidecars carry the streaming `absolute_star` (parity with the desktop
  live pass). Wiring hybrid back into sidecars lands with Phase 3 resume logic.
